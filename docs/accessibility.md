# Accessibility plan and status

**Target:** [WCAG 2.2](https://www.w3.org/TR/WCAG22/) Level AA for every screen and control, plus game-specific accessibility (motor, cognitive, reading and hearing needs) that WCAG does not cover.

**Status (2026-09-24):** every feature below is implemented and checked in the code. The automated checks pass: axe-core in jsdom, axe-core in a real Chromium browser with the WCAG 2.2 AA rule tags including colour contrast, a keyboard-only E2E run and touch E2E runs. **This is not a conformance claim.** No formal audit has been done, and no disabled players or real screen-reader users have tested the game yet. See [Known gaps](#known-gaps-and-risks).

---

## 1. Design principles

1. **The world canvas is decorative.** The Phaser canvas is `aria-hidden` and not focusable. Everything a player needs is also shown as real HTML: where you are, what to do next, who is nearby, every conversation, every puzzle and every menu.
2. **You never have to steer.** The **"Go to…"** list names every person, object and exit in the current place. Choosing one walks you there, or jumps you there with Instant travel, and then talks, examines or leaves. The whole chapter can be finished this way, and the E2E tests finish it this way.
3. **Nothing is timed.** Conversations wait for you. Puzzles have no clock and no penalty. The in-story "time of day" moves only when you make decisions or travel, never in real time.
4. **Sound is never needed.** Every sound goes with something written on screen.
5. **Settings belong to the device and apply at once.** Accessibility needs have to work before a profile is picked, so settings are stored per device, shared by all profiles, and take effect as soon as you change them ([`src/domain/settings.ts`](../src/domain/settings.ts)).

**A real issue found and fixed.** The **locked chapter cards** on the chapter-select screen had been faded with `opacity`, which failed colour contrast (WCAG 1.4.3). The fix keeps full-contrast text and shows "locked" with a dashed border, a different background and the text "Not available yet" ([`.chapter-card--locked`](../src/app/styles/app.css)). Only the browser-level check can catch this kind of problem, because colour contrast is switched off in jsdom. That is why both layers exist.

## 4. Why sound effects need no captions

The game has no voice acting. Its sound effects are synthesised tones ([`synth-audio.ts`](../src/infrastructure/audio/synth-audio.ts)), and **each one plays at the same moment as something already shown in text**:

| Sound effect | Played when | The same information in text |
|---|---|---|
| `interact` | You talk to or examine something | The conversation opens, or a toast labelled "Note:" explains why not |
| `door` | You change place | The HUD place name changes, and the live region announces "Place. Description." |
| `item` | You receive an item | A "Received: …" toast (also in the Satchel) |
| `journal` | You find a clue | A "New clue: …" toast (also in the Journal) |
| `quest` | A quest starts or ends | A "New quest" / "Side quest" / "Quest resolved" toast (also in the Quest log) |
| `solved` | A puzzle is solved | "✓ Solved!" in a `role="status"` region, with an explanation |
| `error`, `page` | *Defined in `SfxId` but not played anywhere today* | — |

Captions are therefore used only for **ambience and music** (row 17), which set the mood but carry no information.

Content authors can also request a sound through the `playSound` effect ([`src/domain/effects.ts`](../src/domain/effects.ts)). Chapter 1 never uses it. Any future use must come with visible text, and a content-validation rule for that would be a sensible addition.

## 5. WCAG 2.2 criteria that are new since 2.1 (A and AA)

| Criterion | Status in this build |
|---|---|
| 2.4.11 Focus Not Obscured (Minimum), AA | **Not verified.** Modals cover the screen. Whether the HUD, toasts or touch pad could hide a focused element has not been checked. |
| 2.5.7 Dragging Movements, AA | No dragging is used anywhere. Sequencing uses buttons, and movement has the Go-to list. |
| 2.5.8 Target Size (Minimum), AA | Primary buttons and HUD buttons have `min-height: 44px`. The smallest buttons (`.button--small`, for example "Change" key and "Conversation history") are 36 px tall, which is above the 24 px minimum. Touch d-pad buttons are 60 px. |
| 3.2.6 Consistent Help, A | Not applicable: the game has no help mechanism that repeats across pages. |
| 3.3.7 Redundant Entry, A | Not applicable: there are no multi-step forms. |
| 3.3.8 Accessible Authentication (Minimum), AA | Not applicable: there are no accounts or logins. |

Announcement timing, reading order in dialogue and how the Go-to list feels in use all need people. | A full screen-reader walkthrough of the chapter on NVDA + Firefox/Chrome and VoiceOver + Safari. Then a small session with young players, including dyslexic readers and switch or keyboard users. |
| G2 | **No formal audit.** | Passing axe is not WCAG conformance. | Have an independent WCAG 2.2 AA audit done before a public release. |
| G3 | **Gamepad works only while exploring.** Button A triggers *interact* only when nothing modal is open. Nothing moves focus through HTML menus, dialogue choices or puzzles, and no pad button opens the Go-to list. **The chapter opens with a conversation, so a gamepad-only player can't get past the first screen.** The Settings hint ("A to talk/examine, Start for the menu") may suggest more than works. | Players who rely on a controller need a keyboard, mouse or touch as well. | Map A to "activate focused control" and the d-pad to focus movement while an overlay is open, add a Go-to button, or reword the hint. Add a unit test with a fake `navigator.getGamepads`. |
| G4 | **Gamepad buttons can't be remapped** and the gamepad has not been tried with a physical controller. | Some players use adapted controllers. | Remappable pad bindings, then a hardware check. |
| G5 | **Toasts and captions vanish after 4.5 s**, and they can't be paused or kept longer. | Slow readers, especially at 200% text, may miss them. Items, clues and quests are also recorded in the Satchel, Journal and Quest log, and toasts are announced to screen readers. But short "Note:" / "Not yet:" messages (why an exit is blocked, for example) are **not stored anywhere else**. | A setting for toast duration, or a "recent messages" list. |
| G6 | **Dialogue live-region timing.** The dialogue box is re-created for every line (it is keyed by node), so its `aria-live` region is inserted already holding the text. Some screen readers don't announce live regions that appear with content already inside. The fallback is that focus moves into the dialogue, whose `aria-describedby` is the full line. | A line could be skipped or read twice, depending on the screen reader. | Check this with real screen readers (G1). If it is a problem, move the live region into a single permanently mounted announcer, like `LiveAnnouncer`. |
| G7 | **Number keys 1–9 pick dialogue choices** through a window-level listener that can't be switched off or remapped. | WCAG 2.1.4 (Character Key Shortcuts) expects single-character shortcuts to be remappable, switchable off, or active only on focus. It is low risk because they only work while a dialogue with choices is showing, but review it. | Add them to the remappable bindings or add an off switch. |
| G8 | **`aria-keyshortcuts` uses display labels.** HUD buttons announce, for example, "Esc" or "↑", but ARIA expects key names such as "Escape" or "ArrowUp". | Minor: some screen readers may read the shortcut hint oddly. | Map key codes to ARIA key names in `Hud.tsx`. |
| G9 | **Reflow at 200% text and 320 px width is not tested automatically.** The overflow check runs only at default text size on the three viewports. | 1.4.4 and 1.4.10 need a check at the extremes. 1.4.12 Text Spacing is not tested either. | Add E2E cases that set text size to 200% on the phone profile. |
| G10 | **In-game high contrast isn't scanned in the browser.** Only the Settings screen is scanned with high contrast on. | Contrast in the HUD, dialogue and journal in high-contrast mode is unverified. | Extend [`e2e/a11y.spec.ts`](../e2e/a11y.spec.ts). |
| G11 | ***Follow my device* motion setting is read when settings are applied.** If the operating system's reduced-motion setting changes during play, the game only notices after a settings change or reload. | Minor. | Listen for `matchMedia('(prefers-reduced-motion: reduce)')` `change` events. |
| G12 | **WebKit / Safari (iOS and iPadOS) not tested.** Only Chromium has been run. | Many families and schools use iPads. VoiceOver on iOS is a key screen reader. | See [deferred-features.md](deferred-features.md) (registry entry `e2e-webkit-safari`). |
| G13 | **The world canvas can't be explored with a screen reader, by design.** | Screen-reader players can't "look around" the map. The Go-to list, the scene announcement ("Place. Description."), the HUD and the journal give the equivalent information and actions. | Confirm this with screen-reader users (G1). Consider adding each place's description to the Go-to dialog. |
| G14 | **No voice-over.** A `voice` volume channel exists, but there are no recordings. | Players who struggle to read rely on screen readers or an adult reading aloud. | Recorded narration later. The game already needs no audio. |
| G15 | **English only.** | — | Pull UI strings out before localising. |
| G16 | **Source links open in a new tab without saying so** (`target="_blank"` in the Journal's "Sources" list). | Can disorient some users (advisory). | Add "(opens in a new tab)" to the link text. |
| G17 | **The pause key doesn't open the pause menu during a puzzle or the end-of-chapter panels.** | Low: those screens have no timer, and puzzles offer **Step away**. | Consider letting pause open over them for consistency. |
